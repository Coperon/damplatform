## Layers

| Layer | Tool | What |
|---|---|---|
| Unit | Vitest | policies, password, token hash, key builder, Zod DTOs |
| Integration | Vitest + Postgres | constraints, DAL tenant scope, transactions |
| HTTP | Vitest request against route handlers or light server | authz matrix |
| E2E | Playwright SHOULD | login, upload happy path, share view vs download, other-tenant 404 |

No production deploy claim without isolation + authz tests (REQUIRED) and a manual or Playwright pass of share + login (SHOULD).

## Characterization (Phase 0, before destructive schema)

Snapshot **current** prototype behavior for:

- Unassigned resources visibility
- M2M resource in two collections
- Grant inheritance CTE
- Login ignoring `status`

These tests document reality. After product cutover they are **replaced** by production-spec tests, not kept as the oracle. Do not silently preserve wrong isolation.

## Isolation matrix (REQUIRED)

Fixtures: tenants T1 T2, users viewer/editor/admin per tenant, operator, one file per tenant.

Assert T1 viewer GET T2 resource id → 404/403.  
T1 editor upload to T2 collection → 404/403.  
T1 admin share cannot include T2 file.  
Operator without acting tenant: library list 400.  
Operator with T1: can read T1 file, still 404 for T2 unless they switch.

## Authorization matrix (REQUIRED)

Table from Spec 01 encoded as tests. One helper `assertDenied` / `assertAllowed`.

## Concurrency

File move vs unique filename: two moves to the same name → one 409.  
Collection delete vs upload into child: transaction isolation; loser errors cleanly.

## Search

Search as T1 never returns T2 filenames even if identical strings.

## CI

Unit tests always. Integration tests require Postgres service. E2E on `main` or nightly if secrets exist; not a blocker for unit CI.

## Test data

Factories in `frontend/server/test/factories.ts`. Never use production credentials. `TEST_DATABASE_URL` separate database.
